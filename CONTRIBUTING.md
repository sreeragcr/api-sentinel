# Contributing to API Sentinel

Thank you for your interest in contributing to API Sentinel!

## Development Principles

- Follow the established architecture and module boundaries.
- Keep domain logic independent of infrastructure frameworks.
- Write tests for new functionality and bug fixes.
- Document important architectural decisions.
- Never commit secrets, credentials, or real customer data.

## Contribution Workflow

1. Fork the repository.
2. Create a feature branch.
3. Implement your changes.
4. Run relevant tests and checks.
5. Submit a pull request with a clear description.

## Branch Naming

Examples:

- feature/project-management
- fix/authentication-error
- docs/architecture-overview

## Commit Convention

We follow Conventional Commits.

Examples:

- feat(project): add project creation
- fix(auth): handle expired tokens
- test(engine): add assertion tests
- docs(architecture): document application boundaries
- chore: update development configuration

## Pull Requests

Pull requests should explain:

- What changed?
- Why was it needed?
- How was it tested?
- Are there any architectural implications?
